## 摘要

已确认的问题：

1. **`restartIfTimeOut` 线程不生效（P1 关键）**
   - [L116](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L116) `global exitFlag` 改的是模块级变量，而 [L135](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L135) `exitFlag = False` 是主循环内**局部变量**，[L137](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L137) 判断的是局部变量 → 线程设的标志永远不生效。
   - 线程只在程序启动时创建一次，40s 后设一次标志即结束，不是"每轮重启后重新武装"的看门狗。
   - 纯计时器（只 sleep 40s），不感知进程退出/地址是否出现。

2. **cpolar 启动即崩溃永不重启（P1 关键）**
   - `process.poll()` 只在"找到地址之后"的可用性监控循环里检查（[L158](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L158)）。

3. **[L133](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L133) 误导日志**：启动后无条件打印"超过 40s 未响应"，与实际情况无关。

4. **`checkAddressAvailable` 注释与行为矛盾（用户已确认：改注释）**
   - 行为：异常 → 返回 False（计入失效并触发重启）；注释却写"超时、连接异常等一律返回 True"。

5. **`deleteLogFiles` 调用在 try 之外**（[L129](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L129)）：`os.listdir` 等若抛异常会拖垮整个看门狗（轻微）。

**2. 改造 `tailLog`：空闲时 yield None 心跳**

```python
def tailLog(logPath):
    """持续读取日志文件新增行；空闲时每 0.5s yield None，供调用方做进程/超时检查。"""
    while not os.path.exists(logPath):
        yield None
        time.sleep(1)
    with open(logPath, "r", encoding="utf-8", errors="replace") as file:
        while True:
            line = file.readline()
            if not line:
                yield None
                time.sleep(0.5)
                continue
            stripped = line.strip()
            if stripped:
                yield stripped
```

## 行为语义（决策记录）

- **超时触发条件**：本周期（本次启动到首次获取地址之间）超过 `CPOLAR_RETRY_DELAY`(40s) 仍未输出地址行 → 重启。
- **获取地址后**：禁用该超时，由现有可用性监控循环负责（404/异常连续 `MAX_RETRY_COUNT` 次 → 重启；进程退出 → 重启）。
- **超时值**：复用 `CPOLAR_RETRY_DELAY`=40s，不新增环境变量。
- **异常判定**：保持"异常 → False"现状，只改注释（用户已确认）。
- **5xx 视为可用**（P6）、推送重试期间不监控（P2）不在本次范围。
