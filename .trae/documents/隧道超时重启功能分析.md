# 隧道超时重启功能分析

## 摘要

`cpolar.py` 的"隧道超时重启"**主流程成立**：隧道失效（404 / 连续异常 / cpolar 进程退出）→ 杀进程 → 清日志 → 重启 cpolar → 新地址重新推送。但存在 **1 个关键缺陷**（cpolar 启动期即崩溃时不触发重启）和 **4 个次要问题**。以下为纯分析报告，不含代码改动。

## 现状分析（主流程梳理）

主循环结构（[cpolar.py](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L120-L181)）：

```
while True:
    deleteLogFiles(...)                    # 清旧日志（符号链接+日期滚动文件+master）
    process = Popen(cpolar, -log=...)      # 启动 cpolar
    for line in tailLog(LOG_PATH):         # 逐行读日志
        if exitFlag: break
        address = extractAddress(line)
        if address:
            # ① 无限重试推送 CF Workers（指数退避，封顶 CF_RETRY_DELAY=20s）
            # ② 可用性监控循环：
            #    进程已退出 → 重启
            #    地址可用(非404) → 重置计数，sleep CPOLAR_RETRY_DELAY=40s
            #    不可用(404/异常) → tryCount--, sleep 1s，减到0 → 重启
    # 循环外：旧进程仍在则 kill，sleep 5s 后回到顶部重启
```

重启触发条件（任一）：
1. `process.poll() is not None` —— cpolar 进程退出（[L151-153](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L151-L153)）；
2. `checkAddressAvailable` 连续 `MAX_RETRY_COUNT`(=3，来自 `.env`) 次返回 False（404 或网络异常）—— [L165-169](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L165-L169)。

## 判定结论

**"基本可用但不完整"**。正常场景（隧道中途挂掉）能正确重启，但以下缺陷会导致"该重启时不重启"或"误重启"。

## 问题清单

### P1 关键：cpolar 启动期崩溃（未输出地址行）→ 永不重启
- 位置：[tailLog](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L102-L114)、主循环 [L129-133](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L129-L133)
- 现象：`process.poll()` 只在"已找到地址"后的监控循环里检查（[L151](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L151)）。若 cpolar 因配置/鉴权/崩溃在写出地址行之前就退出，`tailLog` 会：
  - 日志文件没生成 → [L105-106](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L105-L106) 永久阻塞在 `while not os.path.exists`；
  - 文件生成了但没地址行 → [L111-113](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L111-L113) 永久空转在 `readline()/sleep(0.5)`。
  - 两种情况都永不检查 `process.poll()` → **死进程不会重启**。
- 影响：一旦 cpolar 启动失败，整个看门狗瘫痪。

### P2 中等：无限推送重试期间不监控隧道
- 位置：[L136-146](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L136-L146)
- 现象：推送 CF Workers 是 `while True` 无限重试（退避封顶 20s）。此期间**既不检查进程退出、也不做可用性检查**。若 CF 接口持续不可达（或密码错误导致 401），推送永远不成功，监控循环永远进不去 → 隧道即使已死也不会触发重启。
- 影响：CF 侧故障会连带掩盖隧道故障。

### P3 轻微：`checkAddressAvailable` 行为与注释矛盾（用户已确认：改注释）
- 位置：[L49-63](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L49-L63)
- 现状：`except Exception → return False`（异常会计入失效并触发重启）；注释却写"超时、连接异常等一律返回 True（不当作失败）"。
- 用户决策：**保持行为不变，更新注释**与实现一致（异常视为失效、可触发重启）。
- 需同步更新两处注释文案（L52 括号说明 和 L62-63 的日志语义）。

### P4 轻微：`deleteLogFiles` 在 try 块之外，异常会拖垮整个看门狗
- 位置：[L123](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L123) 调用、[L83-84](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L83-L84)
- 现象：`os.path.dirname/basename`、`os.listdir` 若抛异常（如日志目录不存在、`CPOLAR_LOG_PATH` 为空），不在任何 try 内 → `while True` 直接崩溃退出，而不是走重启。
- （文件被占用时的删除失败已有内部重试+告警，正常。）

### P5 轻微：可用时 40s 睡眠内不感知进程退出
- 位置：[L159](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L159)
- 现象：`time.sleep(CPOLAR_RETRY_DELAY=40)` 期间进程若退出，检测最多延迟 40s。可接受，但可改为分段 sleep + 轮询 `process.poll()`。

### P6 设计确认：5xx 一律视为可用 → 永不重启
- 位置：[L56-60](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/cpolar.py#L56-L60)
- 现象：只有 404 视为失效；若 cpolar 隧道挂掉但返回 502/503（上游不可达），`checkAddressAvailable` 返回 True → 永不重启。
- 这是注释明示的设计（"5xx 不当作失败"）。对"重启 cpolar"而言合理（上游挂了重启 cpolar 也无效），但需确认符合预期。

### P7 文档：`.env.example` 缺少新增的 4 个变量
- 位置：[.env.example](file:///c:/Users/Administrator/Desktop/RemoteGoHome/python/.env.example)
- 现象：`MAX_RETRY_COUNT`、`CF_RETRY_DELAY`、`CPOLAR_RETRY_DELAY`、`CLOUDFLARE_WORKERS_API` 未列入模板，新环境会落到代码默认值（3/20/40 + 硬编码 URL）。建议补全模板。

## 推荐修复方向（仅供参考，不在本次范围）

| 问题 | 建议 |
|---|---|
| P1 | 给 `tailLog` 传入 `process` 或改为在空读时返回"无新行"信号，让主循环每次空转时检查 `process.poll()`；或拆出独立看门狗线程 |
| P2 | 推送重试加最大次数/时长上限，超限先做一次进程/可用性检查，或把监控独立出来 |
| P3 | 按用户确认：只改注释，不动逻辑 |
| P4 | 用 try/except 包住 `deleteLogFiles` 调用，异常走告警+继续重启 |
| P5 | 把 40s sleep 改为每 1-2s 轮询一次 `process.poll()` |
| P7 | `.env.example` 补 4 个变量（附默认值） |

## 验证方式（若后续实施修复）

1. 模拟启动即崩溃：临时把 `CPOLAR_PATH` 指向不存在的 exe → 脚本应在数秒内检测到进程退出并重启（打印"cpolar 进程已退出，准备重启"），而非卡死。
2. 模拟隧道失效：临时让 `checkAddressAvailable` 恒返回 False → 观察 `MAX_RETRY_COUNT` 次后进入重启。
3. 正常联调：真实启动 cpolar，确认推送到 CF Workers 成功且无异常重启日志。
